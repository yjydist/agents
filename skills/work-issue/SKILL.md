# 执行任务与跨 session 接续

围绕一个 GitHub issue 完成当前授权的工作, 将验收和 issue 状态同步作为交付的一部分. 任务可以是实施, 调查或决策, 按本项约定交付, 不把调查擅自变成产品修改. 需要 GitHub issue, 评论, sub-issue 和依赖关系的读写能力及本项任务的执行环境.

执行或管理 issue 时按已有授权同步相关记录; 仅请求阅读, 评估或草稿时交付结论与建议, 不因此修改远程状态. 目标仓库和 issue 身份从指定链接或项目上下文核实, 不能把其他仓库的同号 issue 当成当前任务.

## 恢复本项所需的上下文

- 阅读当前 issue 正文, 最新接续或结论评论, 父目标及必要的上层目标摘要. 有明确的结论指针时按指针读取, 只在存在未解决冲突时补查相关历史, 不默认加载所有兄弟任务或完整对话.
- 已有 issue 没有父目标但结果与验收清楚时直接执行, 跳过不存在的父级同步, 不为了使用本技能新建目标. 若用户指定的 issue 本身是宽泛目标且尚无可执行任务, 使用 [wayfinder](../wayfinder/SKILL.md) 先确定边界.
- 从父目标确认当前方向, 成功条件和本项贡献. 若只给了目标, 读取其任务摘要和依赖, 处理列表分页, 选择前提实际满足且未被占用的叶子任务, 优先解除关键不确定性或交付完整行为, 说明选择理由.
- 前置上下文要包含本项真正依赖的决定, 接口或已验证事实及其证据; 后置上下文要说明后续任务需要本项提供什么. 原生父子关系表示归属, blocking 关系表示执行前提, 不把推荐顺序误读成硬依赖.
- 核对前置结果是否仍然适用且已在当前代码或环境中可用. 前置 issue 因取消而关闭, PR 未合并或成果还在其他分支时, 不能仅凭关闭状态开始依赖它的工作.
- 检查相关代码, 测试, 工作区已有修改和分支或 PR. 先判断本项是否已经完成或部分完成, 复用有效成果, 不按旧任务文本重复实现. 目标或验收存在冲突时解决具体疑点, 不以当前实现反推正确需求.
- 多 session 可能协作时读取现有认领, 在 issue 留下执行者, session 或工作分支与开始时间, 写入后复核. assignee 不能区分同一人的多个 session; 存在冲突时协调任务归属, 不根据时间久就抢占工作.

## 执行与范围反馈

- 明确本项结果, 范围, 验收方式及完成阶段, 如验证通过, 合并或上线. 已有约定直接采用; 含义不明且影响验收时澄清. 普通实现选择自主完成, 不为每步检查或技能切换请求确认.
- 用相关实现与验证完成一个完整行为或明确调查结果. 按实际问题使用诊断, 修复, 重构或审查等能力, 不为普通交付固定加载整套技能. issue 的完成条件不自动授权提交, 合并或部署等额外操作.
- 本项规模应包含理解, 执行, 验证与回写. 发现多个独立结果或范围超出合理 session 容量时, 保留已验证成果, 使用 [wayfinder](../wayfinder/SKILL.md) 调整任务边界和依赖. 不为关票削弱验收, 不将尚未完成的任务伪装成完成.
- 新证据影响父目标, 兄弟任务或依赖契约时, 使用 [wayfinder](../wayfinder/SKILL.md) 修订受影响路线. 若缺少该依赖, 保留具体调整建议与受影响项, 明确尚未完成的路线同步. 用户尚未决定的新方向不能自行作为新目标执行.
- 默认聚焦当前工作单元. 用户只授权一项时不自动执行后续任务; 用户授权持续推进整个目标时, 本项验收回写后选择下一项继续, 不把一项完成或技能切换当成整个请求结束.

## 验收并同步当前事实

- 逐项对照当前验收条件检查实际结果, 覆盖本项相关的边界和失败情况. 记录实际运行的检查, 结果及对应代码版本或 PR. 调查任务记录问题, 结论, 证据和未确认部分; 需要用户决策的结果不由 agent 代答.
- 代码已实现但完成条件还依赖合并, 上线或外部确认时, 保持 issue 打开并注明等待对象和下一次核对入口. 缺少验证不能勾选通过. 后续接续时先核对等待事项, 条件已满足就完成收尾, 不重做实现.
- 任务已满足全部完成条件时, 更新正文中的验收项和当前状态, 留下结果评论与证据链接, 以 `completed` 关闭. 如检查发现原关闭判断有误, 在授权管理范围内重新打开并说明缺口; 新需求产生的工作保留历史完成记录并另建任务.
- 检查本次结果是否也满足相关兄弟任务, 或改变后续前提, 逐项核实再同步, 不批量按关键词关票. 对取消, 重复或替代任务说明去向并以 `not planned` 关闭, 重新核对依赖, 不将取消当作前提已成立.
- 将本项结果的一行摘要和证据指针更新到父目标, 更新推荐下一步. 沿父级核对中间目标与最终 goal 的整体验收, 目标已达成且剩余任务和未知项已处理时记录证据并及时以 `completed` 关闭. 子任务关闭数量不能代替整体验收; 有路线调整问题时使用 `wayfinder`.
- 写入前重读相关记录并保留其他 session 的修改, 避免旧正文覆盖新状态. 写入后回读确认验收项, 评论, 关系与关闭原因. 遇到不确定响应先查询再重试, 不重复评论或建票; 部分写入失败时明确已完成与待同步项, 不宣称记录已全部更新.

## 留下可接手的结果

已完成任务的结果评论应足以支持后续任务: 交付了什么, 哪些决定或契约已经成立, 验收证据在哪里, 哪些已知限制影响后续工作. 父目标只摘要并链接, 不复制完整实现说明.

未完成或等待外部结果时, 在本项正文保留当前状态及最新接续评论的指针, 评论记录:

| 内容 | 接手者需要的信息 |
| --- | --- |
| 已完成与剩余 | 哪些验收项已验证, 哪些仍缺失 |
| 当前成果 | 分支, commit 或 PR, 必要文件入口和未提交修改的位置 |
| 依据 | 实际检查结果, 已确认结论, 会避免重复试错的失败证据 |
| 阻塞与下一步 | 具体等待对象或未解决选择, 下一项可执行动作及判断标准 |

未提交修改只存在本地时明确其可访问范围, 不把本地路径当作其他环境可恢复的交付物, 不为交接擅自提交或推送. 使用共享证据链接传递可用结果, 不复制对话流水账或敏感信息. 结束时更新认领为已完成, 等待或可接续, 避免留下看似仍在工作的占用状态.

最终说明本项实际结果, 验收与 GitHub 同步状态, 父目标是否关闭及后续入口. 写入不可用时交付待同步内容并明确远程状态仍未更新. 后续合并或上线需在新的执行或状态核对中确认, 不承诺 session 结束后自动关闭 issue.
